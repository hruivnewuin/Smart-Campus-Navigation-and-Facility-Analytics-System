  The Facility module is all about keeping track of campus facility records and making it easy to find IDs with a special ID hash table. Each facility is represented by a Facility struct, which holds the facility ID in uppercase (like "F001"), the name of the facility, the main building name, and its category. The records are kept in a std::vector<Facility> for order and also in a custom HashTable for quick ID searches.
  To create the hash, we trim any extra spaces and make the facility ID uppercase, using a polynomial rolling hash with a multiplier of 31 to figure out the hash value, which helps us map to bucket indices.
  When there are collisions, the hash table handles it by using Separate Chaining with a series of buckets, starting with a default capacity of 11. We also check for duplicate IDs while loading the facilities from facilities.txt, so we avoid insertion issues. A collision is counted whenever a new facility hashes to a bucket that already has entries. Once everything's loaded, the FacilityManager gives a summary of the total entries and any collisions that happened.

The Department node represents one department, it stores the name, a pointer to its parent node, a list of child pointers, and it includes the depth. 
The root of the tree has no parent and is placed at a depth of 0.
The DepartmentTree file manages the hierarchy. 
It loads data from the data file and extracts departments.txt. 
Afterwards, It adds new departments using a search by name and then it creates a preorder traversal and an indented dierarchy.
The DepartmentMenu controls the menu interface that uses searching, displaying, and preorder.
The StringUtils helps with string text, it trims whitespace, helps compare text without the conflict of capitalization, and it helps with the pipe formatting.
The code uses a general tree so there is no limit to the amount of children a node can have.
Each node stores its children in a vector of pointers.
This also helps the sibling nodes stay in order of when they were added.
The tree keeps every node, then the destructor frees all the nodes using a loop.
The preorder traversal uses stack, this helps prevent overflow.
When using departments.txt, the first valid line become the root.
When it becomes root its parent is called as "NONE."
Every department after has to name a parent from an earlier line, and its name has to be unique. 
If a line breaks a rule then it is rejected and given a warning display that shows filename, line number, and reason.
In the case a tree is empty, the menu goes on and creates a root without asking for a parent.
